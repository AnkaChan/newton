Precision, solver settings, and what was measured

Actual float32 pipeline

The existing deterministic augmenter produces the geometry in float64, then positions are quantized to float32 before encoding. Origins, F, R, U, sparse coefficients, right-hand sides, Krylov vectors, x iterates, and final corner positions are float32.

The polar step uses native LAPACK SGESDD through SciPy. The solve uses SciPy LSQR with an explicit float32 zero x0. Every matrix-vector input/output and returned solution is dtype-checked. A test traces every observed x/u/v/w/dk recurrence array to ensure float32; there is no hidden float64 vector solve.

SciPy can use Python double scalars for norm, condition, and stopping bookkeeping. Float64 analysis afterward measures differences and residuals between the stored float32 arrays; it does not refine their solutions.

Reconstruction and stopping

Inputs to reconstruction are stored cell origins, polar R and local axes U, canonical topology and spacing, and global positions of the fixed z-min face. Original free corners are never given to the solve. There is no smoothing or regularization.

Gradient rows encode F = RU; center rows encode origin/h. Their residuals are dimensionless and equally weighted. atol = btol = 1e-7, conlim = 1e7, and iteration limit 10,000 per coordinate. Stopping codes and iterations are recorded for every axis.

The true equation RMS is evaluated from the actual stored matrix/RHS and solver displacement after solving, rather than trusting only the recursive LSQR estimate. It is distinct from the corner recovery error and from post-addition coordinate rounding.

Generation uses a canonical 0.25 × 0.25 × 1 m cuboid, h=0.025 m, strength 0.5, and the same automatic three-level hierarchy for all seeds. Geometry screening is performed by the existing float64 augmenter before quantization; the sampled volume/Jacobian minima are recorded, along with the encoded float32 center determinant. No VBD simulation is run.
