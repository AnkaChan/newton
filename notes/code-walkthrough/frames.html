03 Local frames and differentiable assembly

The network proposes a change to each cell’s three deformation axes. Assembly turns those cell proposals into one position for every shared corner. The positions are the persistent shape; frames and axes are derived descriptions rebuilt for a solver query. In the 10 × 10 × 40 grid, 4,000 cells share 4,961 corners. Adjacent cells therefore cannot move their common corner independently.

Read the current deformation from eight shared corners

Each canonical rest cell has side length h, measured in meters. Gather its eight current corner positions in the fixed material ordering. The first column of the center deformation matrix F is the difference between the current centroids of the positive-x and negative-x faces, divided by h. Repeat for y and z. These columns are dimensionless transformed material axes: their lengths retain stretch, and their relative directions retain shear.

F[:, x] = (mean(x-positive face) − mean(x-negative face)) / h
F[:, y] = (mean(y-positive face) − mean(y-negative face)) / h
F[:, z] = (mean(z-positive face) − mean(z-negative face)) / h

The implementation uses an equivalent weighted corner sum, subtracting the first corner before accumulating to reduce translation-related cancellation. A batch produces F: [B, 4000, 3, 3]. This is the trilinear hex deformation gradient at the center; one matrix does not describe every possible warping of eight corners. Those corner positions remain available throughout the solve. See the center-gradient computation.

Separate the coordinate frame from the axes

The code decomposes each center matrix with SVD, forms the rotation R = left × right_transpose, and expresses the axes in that frame as A = Rᵀ × F. Multiplication by Rᵀ converts world vectors into local coordinates; multiplication by R converts them back. Both matrices have three columns, but different jobs: R is an orthonormal coordinate frame, while A carries the actual stretch and shear.

The SVD runs inside torch.no_grad(). Consequently, differentiation treats R as fixed for this query, while A = RᵀF retains its position-gradient path. The frame can be recomputed at the next query; “frozen” does not mean fixed for the entire trajectory.

Current inversion restriction: this extractor rejects a nonpositive center determinant and a smallest singular value below its float32 threshold. The raw nine-entry axes format can mathematically represent an inverted matrix, but this extraction path does not accept one. The energy separately requires positive Gauss-point Jacobians. When optional geometry backtracking is enabled, the mixed solver also shortens proposals that fail its sampled geometry checks. These are runtime restrictions beyond the axes’ representational capacity. Frame checks · Energy checks · Optional acceptance

Turn local axis proposals into a shared displacement

The network outputs target axes in the same local frame as its input. The mixed solver subtracts the current axes and rotates the difference into world coordinates:

local_increment = target_axes − current_axes
D = R × local_increment
new_positions = base_positions + solved_displacement

D is one dimensionless 3 × 3 matrix per cell. Assembly finds corner displacements, in meters, whose deformation gradients best match these proposals. At each of eight Gauss points per cell, G(c,q) differentiates the shared displacement using the rest shape-function gradients. The exact fitting objective is:

minimize over corner displacements δ:
  Σ cells c  weight[c] × (1/8) Σ Gauss points q
      squared_sum_of_entries( G(c,q) δ − D[c] )

subject to:
  δ[fixed] = prescribed_positions − base_positions[fixed]

The context sets weight[c] = Young’s modulus × h³, which has units of joules. The quadrature weights are normalized internally, so rest volume is included once. There is no mass term or implicit-Euler inertia term in this assembly objective. The physical energy is evaluated afterward on the assembled positions. Context weights · Assembly objective

All cells reference one global corner array. Competing targets are reconciled by the weighted fit, rather than by averaging independently moved copies. Prescribed corners are assigned their exact supplied positions. The connected grid requires at least one fixed corner to remove the free translation; this implementation does not supply an unconstrained translation gauge.

A concrete example: with h = 0.025 m, an unrotated cell with A = diag(1, 1, 1.2) measures 25 × 25 × 30 mm. A target diag(1, 1, 1.1) gives D = diag(0, 0, −0.1). For one affine cell with its bottom face fixed, assembly lowers the top by 2.5 mm. For many cells, shared corners make all such requests interact.

The solve fits an increment. A zero proposal preserves the existing warped shape exactly when its prescribed corners are already satisfied. It does not repeatedly reconstruct the entire shape from center axes or discard existing within-cell warping. Incremental behavior

Reuse the factor, differentiate through the solution

Stacking the gradient samples gives a fixed operator G and diagonal weights W. Assembly constructs H = GᵀWG and a target operator B that repeats each cell proposal at its eight samples. With f denoting free corners and p prescribed corners, the linear system is:

H_ff δ_f = B_f D − H_fp δ_p

PARDISO factors this matrix once when the material context is constructed and reuses the factor for its solver iterations and physical timesteps. Current positions and neural weights change the right-hand side, not this matrix. Context replacement builds another factor; there is no single global factor shared by every sampled material. Factors and solves stay float32 on CPU; tensors transferred back preserve the input device. Factor construction · Cached solves

The custom backward pass receives the loss gradient on assembled free corners, g_f, solves H_ffᵀ z = g_f, and applies B_fᵀ z to obtain gradients for the proposed axes. That gradient continues through the world rotation and network. CPU transfers do not sever this custom gradient path. The implementation also returns gradients for base and prescribed positions; it supports first derivatives, with fixed topology, material weights, and factorization. The trainer’s detached iteration and timestep boundaries determine how far state gradients propagate.

Where the rigid prediction enters

The mixed path recomputes mass center, angular momentum, and inertia from the current physical shape, then invokes Newton’s body integrator under no_grad(). Its rotation and translation produce a rigid-guided base. A zero-increment assembly restores prescribed corners, yielding an initialization candidate. The ordinary learned query subsequently assembles from its current candidate. The separate single-material API can also apply an explicitly supplied rigid map during assembly. This guidance does not replace the physical inertial prediction Y. The mixed preparation computes Y separately from physical positions, velocity, gravity, and force. Pins determine translation in this clamped assembly: a uniform translation of its base cancels from the exact constrained minimizer. Newton’s model keeps the pinned particles’ positive masses; the learned solver enforces their prescribed positions explicitly. Physical prediction · Rigid-map semantics · Pinned-particle convention
